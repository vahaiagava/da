# Plan — Portal Marketing: perbaiki logic cacat + Import tanpa AI (MVP yang bisa dipakai)

## 1) Objectives

1. Menutup **cacat logic portal marketing** yang sudah terbukti oleh harness (endpoint/collection/field/form tidak selaras).
2. Menegakkan **SSOT lingkup toko (`account_id`)** untuk seluruh data marketing supaya filter/laporan per akun valid.
3. Mengubah form yang masih **teks bebas** menjadi **select ke master** (akun, produk katalog, host/kreator ter-assign, kategori, kurir) agar data konsisten.
4. Menyediakan **Import tanpa AI** yang deterministik: pilih tipe data → pilih toko (+ host/kreator bila relevan) → download template → auto-map heuristik → mapping manual → preview/validasi → commit → rollback. AI hanya opsional.
5. Menutup **lubang fitur berdampak uang/operasi** (credit note retur, kalender shift livehost, analitik ads/live yang sudah ada endpoint tapi tidak ada jalur UX).

## 2) Implementation Steps (phased, core-first)

### Phase 1 — POC Core Workflow (Import tanpa AI + scope account_id) 
Core yang kalau rusak membuat portal marketing tidak berguna: **data selalu berlingkup toko** + **import deterministik tanpa AI**.

User stories:
1. As staf marketing, saya bisa memilih **tipe import** (Orders/Ads/Live Session/Sales/Content/Discount/Launch/Sample/Returns/Reviews/Complaints) sebelum upload agar sistem tidak “menebak”.
2. As staf marketing, saya wajib memilih **toko/akun** untuk tipe data yang berlingkup toko sehingga hasil import muncul saat difilter.
3. As staf marketing, untuk tipe `Live Session`, saya bisa memilih **host** dan/atau **kreator** yang sudah di-assign ke toko itu agar relasi valid.
4. As staf marketing, saya bisa download **template CSV/XLSX** per tipe import dengan kolom standar agar mudah diisi.
5. As staf marketing, saya bisa preview hasil mapping dengan status **valid/warning/error** sebelum commit dan bisa rollback bila salah.

POC tasks (isolated, minimal, harus hijau sebelum lanjut):
- POC-1: Tambah skrip uji `scripts/poc_marketing_import_noai.py`:
  - Membuat 1 akun marketing + 1 host + 1 kreator + 1 katalog item minimal.
  - Simulasikan import Orders & Ads (CSV kecil) via endpoint baru no-AI.
  - Verifikasi: dokumen tersimpan dengan `account_id` valid dan terbaca oleh endpoint list.
- POC-2: Implement endpoint backend MVP untuk no-AI import (baru):
  - `POST /api/marketing/import-noai/templates/{source_type}` (download template)
  - `POST /api/marketing/import-noai/preview` (upload file + mapping heuristik + validasi)
  - `POST /api/marketing/import-noai/commit` (commit hasil preview, simpan history)
  - `POST /api/marketing/import-noai/{import_id}/rollback` (rollback idempoten)
  - Semua request membawa: `source_type`, `account_id` (wajib untuk tipe berlingkup), optional `host_id`, `creator_id`.
- POC-3: Heuristik mapping deterministik (tanpa AI):
  - exact match (case-insensitive) → sinonim (kamus) → fuzzy `difflib.get_close_matches`.
  - Jika ambigu: tandai warning + minta user mapping manual.
- POC-4: Validasi minimal per tipe data:
  - Orders: `date`, `sku`/`product_name`, `quantity`, `revenue`/`gmv` (minimal 2), `account_id`.
  - Ads: `date`, `spend`, optional `campaign`, `account_id`.
  - Live session: `date`, `duration`, `revenue`, `host_id` (wajib), `account_id`.
- POC-5: Gate baru `scripts/verify_marketing_scope.py`:
  - Membuat pelanggaran sintetis (1 dokumen tanpa `account_id`) → gate harus MERAH.
  - Memperbaiki → gate HIJAU.

Exit criteria Phase 1:
- POC script lulus (import no-AI end-to-end untuk 2 tipe data minimum).
- Gate baru hijau, dan `bash scripts/gate.sh` tetap VERDICT HIJAU.
