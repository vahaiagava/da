4. Sebagai admin, saya bisa mengubah costing (PUT) dan hasil hitung ulang konsisten.

## Phase 2 — V1 App Development (RnD UI verification + UoM picker UI entry points)

### User stories (UI RnD)
1. Sebagai user RnD, saya bisa mengisi **Riset Material** dengan `price_unit` (satuan harga) dan melihatnya tersimpan.
2. Sebagai user RnD, saya bisa membuat **Sample Costing** dan melihat baris kain/trim tampil dengan unit & konversinya.
3. Sebagai user RnD, saya bisa melihat di **Tech Pack** bahwa BOM tersimpan dengan `qty_base/unit_base` + status konversi.
4. Sebagai user RnD, saya bisa menghitung **HPP dari BOM** dan melihat qty terkonversi dipakai.
5. Sebagai user, saya tidak pernah menemui layar putih: empty/loading/error state tampil jelas.

### User stories (UoM picker 6 entry points)
1. Sebagai operator gudang, saya bisa scan penerimaan dalam satuan kemasan (mis. box) dan sistem mengonversi ke satuan dasar.
2. Sebagai petugas opname, saya bisa memilih satuan hitung (counted_uom) dan melihat preview “3 box = 36 pcs”.
3. Sebagai user cutting, saya bisa input pemakaian bahan dengan satuan alternatif tanpa merusak stok.
4. Sebagai user issue material, saya bisa memasukkan `qty_uom` per baris dan sistem menghitung qty_base benar.
5. Sebagai operator put-away/opname gudang, saya bisa memilih satuan scan dan mendapat peringatan bila tidak bisa dikonversi.

### Implementation steps
- A2 (UI proof simpan costing):
  - Jalankan Playwright (`mcp_screenshot_tool`) untuk: login → `#rnd-costing-hub` → buat costing baru → pastikan list terisi + detail baris menampilkan unit & hasil konversi.
  - Screenshot bukti state: empty → created → detail.
- A3 (audit UI R&D end-to-end):
  - Browser test 4 modul: `#rnd-materials`, `#rnd-costing-hub`, Tech Pack, HPP Calculator.
  - Verifikasi: empty/loading/error state, tidak ada console error (hanya warning non-blocking).
- B1 (implement UI pemilih satuan di 6 titik):
  - Reuse `SmartNativeSelect` + daftar unit (boleh adopsi `RnDUnitSelect`/ekstrak jadi komponen generik `UomSelect`).
  - Tambah field unit di payload:
    1) Receiving scan-in: kirim `input_uom`.
    2) Opname aksesoris: kirim `counted_uom`.
    3) Cutting: temukan payload yang mengirim qty → tambah `input_uom/qty_uom` sesuai backend.
    4) Material Issue: per item kirim `qty_uom`.
    5) Put-away: kirim `input_uom`.
    6) Opname3 scan: kirim `input_uom` (+ scan-undo).
  - Preview konversi:
    - Pakai `GET /api/dewi/rnd/uom-options?material_id=...` untuk dapat faktor + base_unit (atau buat endpoint inventori baru jika diperlukan untuk non-RnD), lalu tampilkan “input_qty+uom → qty_base+base_unit”.
  - Error handling: bila mismatch/unlinked → tampilkan warning, tetap bisa submit dengan perilaku lama (base) bila user kosongkan unit.
  - Setelah ubah FE: **jalankan `bash /app/scripts/rebuild_frontend.sh`**.

### Success criteria
- UI RnD: costing yang disimpan muncul di list dan detailnya tampil benar.
- UoM picker: 6 modul mengirim field uom baru tanpa mematahkan perilaku lama (tanpa memilih uom tetap sama).
